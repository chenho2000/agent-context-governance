# 架构、约束与扩展边界

第二次实现审计后的新增入口与行为详见[原理到实现](原理到实现.md)和[逐页审计](二次实现审计.md)。

## 数据层

`objects` 保存完整 JSON、会话内递增序号和 SHA-256；写入之后拒绝 UPDATE/DELETE。`views` 是对象 ID 到派生视图的映射；`pending` 保存已预演计划；`events` 记录 append、pending、commit、recover 和内存操作。`memories` 保存派生事实，`blocks` 保存 Core、代码地图和 PRISM 图。

Sidecar 保存工具输出的 UTF-8 字节。文件名来自对象 ID 哈希；恢复时先验证会话范围，再验证归档字节是否和原始对象相同。恢复一个工具输出不等于重放工具；历史调用参数只供审计，投影会标明不要重新执行。

这是一套本地实验状态库，无网络认证、用户隔离服务或敏感信息加密。模型文本只是数据；`metadata` 是调用方提供的控制面。真实接入时不能让检索网页或模型输出随意设置 `resolved`、`obsolete` 等可信标记。

## 状态与动作

| 视图状态 | 活动请求看到什么 | 原始材料在哪里 |
|---|---|---|
| active | 原始正文 | objects |
| cleaned | 确定性清洗结果 | objects |
| alias | 相同读取的 source ID | source object / sidecar；自己的原始记录也保留 |
| folded | ID、标签、哈希和恢复提示 | sidecar 与 objects |
| masked | 日志首尾各 10% 与中间提示；或保留错误结果、缩短调用输入 | objects |
| hidden | 不发送这个逻辑对象 | objects，只能显式审计恢复 |
| distilled | 有来源标签的派生摘要 | objects |

`prune` 对应 hidden，不是 SQL DELETE。语义上它不再留在活动视图中，所以 Agent 未必知道该去恢复；拥有审计库不能自动弥补检索漏召回。

`keep` 不修改状态；`fold` 写入完整归档再引用；`mask` 只允许显式重复日志或失败输入；`prune` 要求显式 obsolete；`distill` 要求非空摘要并排除稀疏材料。whole-turn 只支持 fold，且轮次中任何受保护对象都会让整个计划失败。

## 保护与依赖

保护根包括：当前轮全部对象、未 resolved 的用户消息、instruction 文档，以及 constraint/protected/live_handle/side_effect/exact_now/in_flight 标记。文档中的“指令”在投影中仍是用户层数据，不会被提升为系统权限。

依赖闭包从保护根、显式 root 和可见别名引用出发，遍历 dependencies。活跃依赖可以被 fold，因为有恢复通路，但不能 mask/prune/distill。`exact_now` 则要求正文立即可见，因此连 fold 都拒绝。

这里依赖图由调用者提供。漏标记依赖会导致错误规划；它不是自动静态分析器，也不能证明没有隐含的语义桥接依赖。默认保护所有尚未 resolved 的用户消息是一种保守策略，代价是有时无法达到预算。

## 消息协议

工具对象在存储中是逻辑 span；发送时原子生成 assistant tool_call 与 tool result。隐藏 span 会一起移除两者；fold/distill 会把过长调用参数替换为历史引用。验证器检查重复调用 ID、孤立结果和缺失结果。

`prompt()` 是便于实验和精确前缀比较的规范化 JSON 文本，不应直接当某一家 API 的请求体发送。`messages()` 才返回结构化消息列表；真实宿主还需要提供与模型兼容的 tool schema、system 指令和供应商格式转换。

## 并发与提交

1. 捕获 Snapshot 和 revision。
2. 在 ThreadPoolExecutor 分支运行 planner。
3. 校验所有动作、保护根、依赖和目标范围，并准备 sidecar。
4. 保存 pending；不更改活动视图。
5. 提交前再次 rehearsal。
6. 在 SQLite `BEGIN IMMEDIATE` 事务中比较 revision，检查 busy=0，再一次性切换视图并清除 pending。

因此，在第 5、6 步之间发生 append 也不会被漏掉。数据库连接按操作创建，避免把一个 SQLite 连接跨线程使用。进程崩溃不应出现半个视图提交；但 sidecar 是数据库外文件，崩溃可能留下未引用文件。没有实现自动归档清理或迁移协议。

`Store.commit` 是底层机制；学习和扩展时应通过 Governor/Runtime 提交策略动作，而不是绕过语义校验直接操作 views 表。

## 缓存成本

令 I 为原请求在首个修改位置之后的单位数，J 为新请求对应后缀长度，S=I−J，未来发送次数为 N，缓存读取价 r、写入价 w，尚未支付且只在提交路径产生的成本为 G。

缓存有效时，提交净收益：

```text
N × S × r − J × (w − r) − G
```

缓存已经过期时：

```text
S × w + (N − 1) × S × r − G
```

正值才按经济性提交；若现状超过 hard_limit，允许为满足容量而提交，但候选视图本身必须满足上限。硬限制优先于缓存经济，不优先于证据保护。

提交时 planner 已经运行，其费用是沉没成本。规划前决定“是否值得启动治理”则应该把预估 planner 费用算进去。本原型的自动触发使用高水位与事件，并未训练能预测未来 N 或恢复概率的控制器；`future_calls` 和 expired 都是显式实验参数。

`PrefixCache` 只模拟可复用的精确词法前缀、TTL 与模型范围，忽略真实最小缓存长度、计费粒度、逐块过期与服务负载。`kv.py` 是两层因果依赖的标量演示，不测 GPU 加速，也不实现 KV 驱逐或量化。

## 两种预算

PRISM / SimpleMem 的 budget 限制所选正文的教学单位，不含 JSON 包裹。`Runtime.retrieve_first` 再计算包括当前约束、问题、来源标记与模板在内的完整请求容量；装配器逐条尝试完整证据，记录因正文或序列化请求预算而跳过的条目，并可预留输出空间；保护内容与问题本身超限时才直接失败。

GC 比较的 before/after 包括工具包裹和历史引用，所以折叠短内容有可能变长。规则压缩、LLMLingua 与本地摘要也不承诺一定变短或语义正确；应用端需要根据结果决定 fold、重检索或拒绝。

MemGPT 检查 Core 容量以及提供给模型的 state 容量。教学计量不含供应商所有协议 token；真实接入要用目标模型 tokenizer 计入 system、工具 schema、输出预留与服务限制。

## 检索与记忆的取舍

PRISM 使用全量节点向量、typed edge 正权搜索和内容重排。N3 默认 BM25，可选模型返回候选 ID 列表；非法或重复 ID 被拒绝。检索选择完整 episode，不把一条证据截成任意首尾；代价是某条长证据可能完全装不下。

SimpleMem 使用 (session, entity, slot, value, date) 规范键合并。模型看到已有记忆以帮助规范化；离线分支不识别同义改写。显式 supersedes 可精确指向被更正记录，旧 correction 标志只在较早观测中推断候选；新旧记录都留下，窗口事务拒绝更正环。没有事实置信度学习、复杂双时态推理、跨语言实体消歧或冲突自动裁决。

向量、词法和符号视图通过排名融合，避免直接把余弦与 BM25 原始分数相加。调用者可给实体和日期范围；模型查询规划不能悄悄扩大档案范围。

SleepWorker 可重复摄取并合并来源。`put_memory` 已通过 SQLite 事务将来源和 supersedes 做集合并集，防止并发写入覆盖来源。不同事实之间的复杂更正关系仍需要独立的业务冲突协议。

## 分层模型与宿主边界

`compression.cascade` 依次尝试规则、显式传入的 LLMLingua-2、显式传入的本地模型；达到预算就停止。Governor 是对象动作的权限关口。不能把所有低层压缩结果直接写回原文。

CLI 的 Lingua 命令是直连上游压缩器的独立实验，刻意让你观察其对任意文本的影响；把它用于 Agent 时，应走受保护路径。三代算法代码来自上游包，本项目只是薄适配，权重加载和硬件兼容性由上游承担。

没有注入 Claude Code、Codex 或 OpenCode 当前任务的隐藏上下文。这个项目拥有自己的请求投影层，因此可以合法演示历史编辑。要安装到真实宿主，应先确认宿主提供发送前消息转换或等价接口，而不能假设普通工具就能重写历史。

## 验证范围

测试验证原始记录不可变、归档损坏检测、会话范围、版本/范围去重、别名依赖、过期计划、在途工具、稀疏证据、工具协议、容量、成本符号、持久化检索、记忆日期和更正、代码地图过期、模型传输契约、合成样本无未来字段泄漏，以及完整 CLI 案例。

测试没有验证真实模型摘要的事实忠实度、论文 benchmark、真实 API 缓存命中率、模型推理性能或训练效果。扩展时建议分别测“证据可达率”“模型正确使用证据的比例”和“单位成功任务总成本”，不要只测输入长度下降。
