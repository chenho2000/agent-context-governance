# 文章方法 → 实现与验证

**更新：第二次逐页审计发现并补齐了上一版缺口。最新逐项状态、测试与限制以[二次实现审计](二次实现审计.md)及 [coverage.json](coverage.json) 为准；下表保留基础方法导览。**

这份表的“覆盖”指可以学习和实验核心机制，并不表示完成原项目全部功能或复现论文成绩。官方论文/仓库与本项目代码分开列出，避免把不同方法混成同一种算法。

## 1. 全量方法清单

| 文章路线 | 本项目入口 | 真正实现的机制 | 明确边界 |
|---|---|---|---|
| Self-GC | `Governor` | 稳定 ID、依赖闭包、keep/fold/mask/prune、XML 计划、快照分支、预演、pending、版本原子提交、按 ID 恢复 | 默认规则规划；模型规划为可选 Ollama；没有官方训练 planner 或任务成绩复现 |
| Mark / Sweep / Compact | `dependency_closure`、`rehearse`、`messages` | 标记任务根和桥接依赖；改变视图；重建合法工具消息对 | 不是真正 JVM GC，不以图闭包证明语义完整 |
| PRISM N1 | `Prism.retrieve(n1=True)` | 四层锚点、正权最小成本搜索、有界 hop、最多一次关系桥接 | 小型图由程序显式构建；不是论文完整图构建器和候选搜索实现 |
| PRISM N2 | `n2=True` | query intent 对同类型边打折，记录每步成本 | 教学折扣 0.4；不是论文拟合参数 |
| PRISM N3 | `n3=True` | 仅按 episode 内容重排，整体证据预算选择，可选模型重排 | 默认 BM25 近似语义裁判；选择现有 episode，不自动保证摘要无损 |
| PRISM N4 | `route` | 关键词 → 原型向量；显式模型可处理未命中关键词的问题 | 原型是固定短文本；没有复刻论文分类器性能 |
| SimpleMem 窗口与 gating | `SimpleMemory.ingest` | 可配置 window/stride；空事实不写入；模型抽取新事实；显式时间锚定、绑定、来源验证 | 离线依赖 facts 标注；不将字符熵冒充 semantic entropy gating |
| SimpleMem 三合一写入 | 同上 | 原子事实字段、显式指代替换、相对日期转绝对日期 | 未标注/模型不能确认的指代不能自动补全；来源存在不代表内容已被蕴含证明 |
| Online Semantic Synthesis | 同上 | 规范化槽位键合并来源；模型可参考已有记忆进行抽取；变化与 correction 分开 | 离线是结构化合并，不能自主识别不同措辞的等价事实 |
| SimpleMem 三视图 | `retrieve` | BM25、向量、实体/时间过滤、RRF 合并、来源和预算 | 默认哈希向量；Sentence Transformers 是真实可选后端；没有 ANN 大规模索引 |
| Intent-aware retrieval planning | `route`、`SimpleMemory.retrieve(model=...)` | 意图识别、多个查询、top-K 上限、过滤与总预算 | 默认一个查询；查询扩展质量依赖模型 |
| MemGPT | `MemoryAgent` | Core、Recall、Archival；工具调用、分页、heartbeat、警告与有限执行步数 | 没有完整对话模型宿主和 MemGPT 官方提示词/调度系统 |
| Letta Sleep-time | `SleepWorker` | 在后台线程基于快照整理记忆、合并写入、保留来源版本 | 机制扩展，不是 Letta 服务接入，也不是 SimpleMem v3 的必备阶段 |
| LLMLingua | `Lingua('llmlingua')` | 调用官方 `PromptCompressor`，可指定因果 LM 与压缩率 | 神经模型不在默认实验运行；没有重写困惑度压缩算法 |
| LongLLMLingua | `Lingua('longllmlingua')` | 官方问题条件参数、重排与动态压缩配置 | 需明确 question；单文本 CLI 不能体现多文档排序的全部收益 |
| LLMLingua-2 / BERT 档位 | `Lingua('llmlingua2')`、`cascade` | 官方 token 分类压缩器、编码器档位接入 | 没有训练对象存活分类器；没有把 token 分数当 GC 决策 |
| Prompt/KV caching | `PrefixCache`、`commit_value`、`kv.demo` | 精确教学前缀、模型隔离、TTL、命中与写入成本、因果注意力演示 | 不访问供应商真实 KV；无最小缓存块阈值或真实 tokenizer |
| Cache-safe fork | `prompt`、`Governor.fork` | 保留主会话快照，规划不修改主视图，提交时算后缀失效成本 | 新增 compaction_request + generate_messages 可发送不变结构化前缀；普通 generate 规划路径仍不复用主请求前缀，二者都不保证服务命中 |
| claude-code-context-diet | `preprocess` | ANSI 清理、连续日志去重、大结果折叠、相同读取引用 | 机制参考，无 Claude Code hook 安装；稀疏格式受保护 |
| tokenmax-mcp | `CodeMap` | Python AST、持久化符号/行号/版本、符号读取、过期检查 | 支持 Python，不是多语言 MCP server；未复刻原项目工具开销 |
| cctx-optimizer | `Ollama`、`compress(local)`、`SimpleMemory` | 本地工具文本摘要、可恢复历史、跨进程持久记忆、代码结构索引 | 是组合机制，未嵌入其宿主；轮次摘要由 TurnSummaries 实现，非原项目全功能 |
| OpenCode DCP | `preprocess`、`Governor`、`messages` | dedup、obsolete pruning、distill、whole-turn fold、错误输入缩短且保留结果、发送视图独立于记录 | 没有 OpenCode 插件 hook；完整工具结果包裹由本地 runtime 控制 |
| 规则 → 编码器 → 本地 LLM → Planner | `cascade` + `Governor` | 前三档压缩选定文本；第四档对对象提出治理计划，统一受保护执行 | 有意不强行让所有对象依次经过全部档位；预算不足明确报错 |
| 高水位/事件触发 | `Runtime.tick` | 使用率阈值、阶段结束/空闲/工具突发触发；在途工具暂停提交 | 事件由调用者提供，没有常驻守护进程或后台轮询 |
| 两种模式 | `Runtime.retrieve_first`、`tick` | 外部证据检索后组装请求；既有历史原地投影视图治理 | In-Place 仍需要本地持久记录才能 exact recover；不承诺完全无存储恢复 |
| SFT / DPO / 慢循环 | `evaluate_trial`、`export` | 无未来泄漏的样本输入、匹配状态的偏好对、失败统计 | 合成证据裁判与数据候选，未训练模型、未进行真实任务偏好评测 |

## 2. 七个架构决策与四组件

| 决策 | 代码位置 | 可观察结果 |
|---|---|---|
| 对象建模 | `types.py`、`store.py` | `session:kind:seq`、不可变 body、metadata、dependencies |
| 入域前处理 | `preprocess.py` | 清洗、引用、sidecar 的 trace |
| 分层决策权 | `compression.py`、`governance.py` | token 文本压缩和对象权限分开 |
| 触发时机 | `runtime.py` | below_threshold / busy / pending / committed |
| 缓存经济 | `cache.py`、`Governor.commit` | 共同前缀、被重写后缀、净收益、硬上限 |
| 非破坏编辑 | `store.py`、`projection.py` | 原文、视图、请求、恢复记录分离 |
| 数据飞轮 | `flywheel.py` | SFT/DPO JSONL、跳过不可比较样本的原因 |

四组件的职责对应如下：

1. **Preprocessor**：`preprocess.py`，处理明确的形式冗余。
2. **File State Tracker**：读取对象的 path/version/range/content hash 与 `CodeMap` 的版本地图，避免跨版本或不同范围误去重。
3. **GC Controller**：`Runtime` + `Governor`，负责触发、规划、预演、pending 与提交。
4. **CacheGuard**：`commit_value` 与 `PrefixCache`，把前缀破坏和未来复用次数纳入决定。

## 3. 对原文采用的修正

- PRISM 是检索与压缩联合路线，因此实现保留 N3；不把“存量全部保留”理解为每次都发送全部内容。
- SimpleMem 按所提供 v3 的 online synthesis 与 intent-aware retrieval 讲解。后台 sleep 是另一个可组合扩展。
- window=20、stride=15 是本原型的显式选择，对应重叠 5 条；不假装解决论文中 stride 与 overlap 表述的歧义。
- LLMLingua-2 接的是 token 压缩接口，不能宣称已经具有安全对象垃圾回收能力。
- 精确归档只保证取回原始字节，不能保证 Agent 一定知道何时恢复。
- 缓存收益计算中，已支付的 planner 费用不再作为提交时的额外成本；整个治理任务的总费用仍应计入 planner。
