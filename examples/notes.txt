Ada reviewed the payment retry plan on September 5. Tests showed that a network request timeout does not mean the gateway has not charged the customer. If the application immediately sends the charge request again, the customer may be charged twice.
The team decided to use a stable idempotency key for each payment operation. Amounts must be represented as integer cents, and duplicate charges must never be accepted as a cost of retries.
Background discussions covered connection pools, log formatting, and test directory organization. These discussions have not changed the payment logic. The key conclusion to retain is that retries must reuse the same idempotency key and check the gateway's result for that key.
